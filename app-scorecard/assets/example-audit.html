Noncompensatory blockers

Three gates, all fixable in days

The framework treats security, privacy, accessibility and compliance as gates. A high score elsewhere cannot offset these.

Legal · privacy

No privacy policy, terms, or account deletion

Google sign-in collects email and name. Per-email search queries, AI usage, and reflections are written to the store. No route under app/ names privacy or terms. No way for a user to delete their account or data. Stripe billing runs without posted terms.

Analytics · measurement

Value telemetry is a no-op

@vercel/analytics is mounted in the layout, but the app runs on a VPS under systemd, not Vercel. It sends nothing. The store logs searches, not outcomes. Activation, retention, and task success cannot be computed by anyone.

Accessibility · audience

No accessibility pass on a product for an older audience

Zero prefers-reduced-motion rules despite intro and explainer animations. Focus styles on 21 sites across ~60 components. Five images, five alt attributes, so images are fine. No keyboard or screen-reader test recorded anywhere. Sepia contrast already needed one fix.

Product strategy
3/ 5
Observed

The wedge is crisp in AGENTS.md: source-based quote finder for pastors in one region. But the route list tells a different story. Search, Ask, Today, Topics, Photos, Journeys, Circles, Bench, Deep Study, Bible cross-references, World Scripture, translation, TTS. Twelve surfaces shipped in weeks with no stated non-goals.

  • Target user and job stated
  • Differentiation is outcome-based (grounded vs invented)
  • Non-goals written down
  • Scale plans wait for validation

Write three non-goals into AGENTS.md and freeze new surfaces until the value event is measured.

Value proposition
4/ 5
Observed

19,638 citation-tagged quotes, full source documents for read-in-context, an attribution guard with tests, and AI that is told to cite or stay silent. Every feature maps to the job "find a quote I can stand behind." The framework's ideal: features connected to a high-priority job, with the social and emotional weight (a pastor's credibility) built in.

  • Maps to a user job
  • First-value event identifiable (cited quote used)
  • First-value event defined in code
  • Alternatives clearly worse at the job

Name the value event in README so every feature is judged against it.

Market fit
unknown
Refused

The framework is explicit: product-market fit is a state of evidence, and it cannot be read from a codebase. There are no cohort files, no renewal records, no repeat-use metric. A pricing page and Stripe integration are not evidence of willingness to pay.

  • Cohort retention
  • Repeat choice
  • Organic pull
  • Any of the above instrumented

See Analytics. Nothing here moves until that does.

User research
2/ 5
Observed

A feedback form and a feature-request dialog exist, and Search Lab collects blind relevance judgments. That is research infrastructure. What is missing is any record that research changed a decision: no research notes, no task-success measurement, no observed sessions in the repo or docs.

  • Feedback channels built
  • Retrieval quality judged blind
  • Task success measured
  • Decisions traceable to research

A `docs/research/` folder with one page per study and the decision it drove.

Analytics / KPIs
1/ 5
Observed · gate

The store records searches, users, AI cost, quotas, and subscriptions. Admin renders counts. That is an operations log, not a measurement system. No North Star, no activation definition, no event taxonomy, no guardrails. The Vercel Analytics import is dead weight off-platform.

  • North Star or value metric defined
  • Activation defined as value, not sign-in
  • AI cost tracked per model
  • Client analytics actually shipping events
  • Vanity metrics identified as such
  • Data quality checks (store is append-only JSONL, unvalidated)

Replace the Vercel import with self-hosted Umami or Plausible, and fire one event: quote copied / shared / benched.

Experimentation
3/ 5
Observed

Search Lab is real: four retrieval strategies behind randomized A–D labels, method names revealed only after judgment, append-only trials, scoring tests, an export. Rare for a project this size. It covers one thing, retrieval ranking, and there is no framework for product experiments.

  • Hypothesis before result (blind labels)
  • Randomization correct
  • Power or minimum detectable effect considered
  • Guardrail metrics
  • Any experiment outside retrieval

Keep it. Add a guardrail column (citation completeness) to the judgment schema.

Growth / virality
1/ 5
Observed

A share-quote button and an install banner. No loop: sharing a quote does not bring the receiver into the product with value, nothing invites, nothing compounds. The framework wants a loop coupled to the core job. Circles (shared study groups) is the closest candidate but has no invite mechanics.

  • Share exists, receiver value unclear
  • Growth loop diagrammed
  • Invite-to-activation measured
  • No dark patterns

Shared quote links should land on a cited, readable quote page with one search box beneath it.

Monetization

Observed

Stripe checkout, portal, and a signature-verified webhook as the source of truth for entitlements. Tier gating enforced server-side on Ask, Deep Study, TTS. Search stays free, so the core value event is not paywalled. Clean mechanics. What is unknown is whether anyone converts.

  • Payer and user identified
  • Webhook verified, entitlements server-side
  • Core value not paywalled
  • Conversion, churn, margin monitored

Log AI cost per subscriber against subscription revenue in admin. One number.

User experience, retention, trust
Onboarding
2/ 5
Observed

Search works logged out, which is the right call: value before sign-in. But the home page carries an intro animation, feature cards, feature sections, a pricing preview, a support CTA, a closing CTA, and search tips alongside the search box. Ask requires sign-in with no in-context explanation of why. The framework and Apple's guidance both say: let the user experience the product before nonessential content.

  • Core action available without account
  • Nonessential content deferred
  • Permissions (sign-in) requested in context
  • Time-to-value measurable

Home page becomes search box, topic chips, Search/Ask toggle. Everything else moves to About, Help, Pricing.

Retention
unknown
Refused

Daily-word streaks exist, which is a retention mechanic, not a retention measurement. No cohort table, no return-interval calculation. The natural cadence is weekly for sermon prep and daily for devotional reading; neither is tracked.

  • Cohort retention at weekly interval
  • Return mechanism exists (streaks, install banner)
  • Return mechanism measured

Weekly active accounts by sign-up week. One query over the existing search log.

Engagement
unknown
Refused

Searches per user is available in the store. The framework says search count is activity, not value; "meaningful engagement" has to be defined first, and it is not. Deep-study quota usage and bench adds are the nearest proxies and neither is surfaced.

  • Meaningful engagement defined
  • Time-on-site not treated as a goal
  • Depth and breadth per user

Define it: a session with at least one quote copied, benched, or read in context.

Interaction design
3/ 5
Observed

base-ui and shadcn primitives, toast feedback via sonner, modals for source detail and read-in-context. Competent and predictable. Not user-tested, no mis-tap or abandonment data, and animation components have no reduced-motion path.

Accessibility
2/ 5
Observed · gate

Semantic primitives help, and images have alt text. But there is no WCAG pass on record, focus visibility is inconsistent, and motion cannot be disabled. Reading preferences (font size, sepia) show care for legibility, which is exactly the right instinct for this audience, so the gap is process rather than intent.

  • Keyboard focus visible (21 sites)
  • Images have alt text (5 of 5)
  • Labels and aria on controls (24 sites)
  • Reduced motion
  • Screen-reader test performed
  • Contrast (one fix already needed)

Run axe on Search, Ask, Today. Fix what it lists. Record the date in AGENTS.md.

Security / privacy
3/ 5
Observed

Solid for the data class. Google OAuth code flow with an HMAC-signed cookie, no third-party auth library, no database to breach. 34 server-side 401/403 checks across API routes. Stripe webhook verifies signatures. Secrets live in gitignored env files and root-only systemd EnvironmentFiles. Per-user quotas cap AI spend. What is missing is data lifecycle: no retention or deletion policy for the per-email logs, and moderation of wiki contributions fails open by design.

  • Authorization server-enforced
  • Secrets out of repo
  • Payment webhook verified
  • Abuse quotas on AI routes
  • Retention / deletion policy
  • Threat model written
  • Dependency scanning

A `/api/auth/delete` route that removes the user's rows from the store, plus one paragraph on retention.

Legal / compliance
1/ 5
Observed · gate

A public app taking payments and storing personal data with no privacy policy, no terms, and no deletion path. Separately, the corpus is a publisher's copyrighted material and the repo does not document the permission under which it is redistributed and paraphrased by AI. The photo wiki will add likeness and consent questions. The framework is clear that an AI checklist cannot establish compliance; a human needs to.

  • Privacy policy
  • Terms of service
  • Account deletion
  • Corpus licence documented
  • Regional rules for NY users (SHIELD Act)

Privacy and terms pages this week. Corpus permission in writing from the region before the public launch widens.

Engineering, scale, systems
Performance
3/ 5
Observed

Search is an in-memory cosine over 58 MB of embeddings, fast at this scale. Related-verse and explain results are cached in the store and pre-warmed by scripts. Risk sits at the edges: every semantic query first hits Ollama for the query vector, on a single VPS with 4 GB swap. No p95 measured, no budget set. The 20 MB quotes.json is bundled into the server, not the client, which is correct.

  • Heavy data server-side only
  • AI results cached and pre-warmed
  • Latency budget for search
  • Tail latency measured
  • Low-end device or slow network tested

Log search duration to the existing store. Read p95 once a week.

Reliability
2/ 5
Observed

Keyword fallback if Ollama is down is real graceful degradation. Help bot degrades to static text without its key. Moderation fails open. Those are good instincts. But 24 of 39 API routes wrap in try/catch, no health endpoint, no monitoring, no SLO, and an append-only JSONL store with no backup step in deploy. A single box in each tier.

  • Search degrades gracefully
  • Error handling (24 of 39 routes)
  • Health endpoint or uptime check
  • SLI or SLO for core journeys
  • Store backup before deploy

`/api/health` returning Ollama and OpenAI reachability, checked by a scheduled uptime job.

Engineering practices
3/ 5
Observed

50 tests pass across attribution, context building, scoring, Bible chunking. 14 runtime dependencies, deliberately no auth library and no ORM. CI auto-deploys main to dev. Deploy script separates dev and prod branches with a release marker so main can never land on prod by accident. On the other side: ESLint does not run (config migration pending), there is no prod CI, and rollback is a manual git operation.

  • Critical logic tested
  • Lean dependency set
  • Dev CI
  • Prod isolated behind a release branch
  • Lint runs
  • Documented rollback
  • Observability (console only)

Fix the ESLint flat-config migration so `npm run lint` runs again, then add it to CI.

Scalability
2/ 5
Observed

Right-sized for hundreds of users. A 10× scenario breaks in known places: the JSONL store reads whole files on request (10 sync reads in store.ts), one Ollama process serializes embedding calls, and one Node process holds 90 MB of embeddings. None of this is wrong today; the framework warns against premature distribution. It is unplanned rather than unscalable.

  • No premature complexity
  • 10× scenario written down
  • Store hotspot acknowledged
  • AI cost scales with tier gating

One paragraph in AGENTS.md: at what user count the store moves to SQLite, and who decides.

Localization
2/ 5
Observed

English, Korean, Japanese in a hand-rolled i18n module with 60 keys, a language toggle, and a translate route. Twenty of 53 components read from it, so the rest are English-only. No plural or date rules, no layout-expansion test for CJK. The audience genuinely spans these three languages, so this matters more than for most apps.

  • Strings externalized (20 of 53 components)
  • Three target locales present
  • Plural, date, number rules
  • Layout tested in Korean and Japanese

Grep for hard-coded English in the 33 untranslated components and move the header, search, and results strings first.

Design system
3/ 5
Observed

Tailwind v4 tokens, shadcn and base-ui components, next-themes for dark mode, reading preferences layered on top. Consistent. No visual-regression check and no governance doc, which is proportionate for one maintainer.

  • Semantic tokens used consistently
  • Accessibility states from primitives
  • Visual regression
  • Platform conventions kept

None needed now.

Final judgment

Strong bones, no instruments, three doors open

Strongest reasons to win

  1. The value proposition is unusually clear and the corpus, attribution guard, and read-in-context make it real.
  2. Engineering discipline: tests, lean deps, server-side gating, a prod branch that main cannot reach.
  3. Search Lab. Blind retrieval evaluation is something most funded teams never build.

Strongest reasons to fail

  1. Nothing measures whether the product works. Every roadmap decision is intuition.
  2. Legal exposure grows with every sign-up and every Stripe charge made without terms.
  3. Surface sprawl. Twelve features before one is proven dilutes both the product and the maintainer.

Critical unknowns

  • Weekly return rate of signed-in pastors.
  • Share of searches ending in a used quote.
  • p95 search latency on the production VPS under real load.
  • Corpus redistribution rights.
Highest-leverage fixes, in order

One week of work closes all three gates

None of these needs a design decision. All are reversible. Together they move the verdict from Iterate to Conditional Go.

  1. Privacy policy, terms, and an account-deletion route.
  2. Swap the dead Vercel import for self-hosted analytics. Fire one value event.
  3. Reduced-motion block, `error.tsx`, `not-found.tsx`, axe pass on three pages.
  4. Fix ESLint, add it to CI. Add `/api/health`.
  5. Write three non-goals. Stop shipping surfaces until step 2 has four weeks of data.
